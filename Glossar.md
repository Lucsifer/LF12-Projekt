# Glossar
|Begriff|Beschreibung|
|--|--|
|Summoner|Spieleraccount in League of Legends, eindeutig identifiziert durch Summoner Name und Summoner ID|
|Riot Games API|Offizielle Programmierschnittstelle von Riot Games, über die Spieldaten wie Match‑History, Ranglisten oder Summoner‑Informationen abgerufen werden können.|
|Match Data|Strukturierte Spieldaten eines einzelnen Matches, z. B. Kills, Deaths, Assists, Gold, Items, Spielzeit.|
|Champion|Spielbarer Charakter in League of Legends, dessen Statistiken über die API abrufbar sind.|
|Next.js|React‑basiertes Webframework für serverseitiges Rendering, API‑Routen und performante Webanwendungen.|
|Tailwind CSS|Utility‑First‑CSS‑Framework, das schnelle und konsistente Gestaltung von Benutzeroberflächen ermöglicht.|
|GUI (Graphical User Interface)|Grafische Benutzeroberfläche der Webapp, über die Nutzer Summoner‑Daten eingeben und Ergebnisse sehen.|
|Node.js|JavaScript‑Laufzeitumgebung für serverseitige Anwendungen|
|Express|Minimalistisches Webframework für Node.js, häufig genutzt für API‑Routen.|
|API‑Endpoint|Eine spezifische URL, über die Daten von der Riot API oder der eigenen Backend‑API abgerufen werden.|
|Rate Limit|Begrenzung der Anzahl an API‑Anfragen pro Zeitfenster, die von Riot Games vorgegeben wird.|
|Redis|n‑Memory‑Datenbank, ideal für Caching. Reduziert API‑Anfragen und beschleunigt Antwortzeiten.|
|PostgreSQL|Relationale Datenbank für persistente Speicherung, z. B. Nutzer‑ oder Match‑Daten.|
|Caching|Zwischenspeicherung häufig genutzter Daten, um Performance zu verbessern und API‑Limits zu schonen.|
|Docker|Plattform zum Verpacken von Anwendungen in isolierte Container.|
|docker‑compose|Tool zum Starten mehrerer Container als zusammenhängende Anwendung.|
|Container|Isolierte Umgebung, die eine Anwendung samt Abhängigkeiten enthält.|
|CI/CD (Continuous Integration / Continuous Deployment)|Automatisierter Prozess, der Code testet, baut und auf den Server deployt.|
|GitHub Actions|Automatisierungsplattform, die eure CI/CD‑Pipeline ausführt.|
|Nginx|Webserver und Reverse Proxy, der Anfragen entgegennimmt und an eure Anwendung weiterleitet.|
|Reverse Proxy|Vermittler zwischen Client und Backend, der Sicherheit und Struktur verbessert.|
|HTTPS|Verschlüsselte Verbindung über SSL/TLS‑Zertifikate (z. B. via Certbot).|
|Firewall|Sicherheitsmechanismus, der Netzwerkzugriffe kontrolliert und schützt.|
|SSH|Sicheres Protokoll für Serverzugriff und Deployment.|
|Uptime Kuma|Monitoring‑Tool, das Verfügbarkeit, Antwortzeiten und Status eurer |
|Health Check|Automatisierte Prüfung, ob Dienste korrekt laufen.|
|Logs|Protokolle, die Fehler, Anfragen und Systemzustände dokumentieren|
